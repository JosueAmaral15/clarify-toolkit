## 📝 Documentation Standards

### Organization Principles
1. **Content-based categorization** - Docs organized by what they contain
2. **Programmer ownership** - Programmer-specific work in dedicated folders
3. **Logical hierarchy** - Related docs grouped together
4. **No loose files** - Root contains only navigation files (README, INDEX, TASKS)

### File Naming
- Use descriptive names with context
- Include programmer suffix for programmer-specific files (e.g., `_COM4.md`)
- Use UPPERCASE for major documentation files
- Use lowercase for guides and tutorials

### Where to Put New Docs
- **Action plans** → `action-plans/{reading,development,cleanup,investigation}/`
- **Session logs** → `sessions/` (or `sessions/phases/`, `sessions/steps/`)
- **Reports** → `reports/`
- **Programmer-specific** → `programmers/comX/`
- **Features** → `features/`
- **Guides** → `guides/`
